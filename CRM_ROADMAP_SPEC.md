## 1. Стек технологий и стандарты разработки

* **Фреймворк:** Next.js 16 (App Router, Turbopack, React 19, Server Actions, Route Handlers).
* **Язык:** TypeScript 5.x (строгая типизация `strict: true`, никаких `any` в финальном коде, валидация через интерфейсы в `lib/types.ts`).
* **База данных & Auth & Storage:** Supabase (PostgreSQL 15+, Row Level Security, Supabase Auth, Storage private bucket `client-documents`).
* **UI & Стилизация:** Tailwind CSS, CSS переменные тем оформления (`data-theme`), иконки `lucide-react`.
* **Работа с таблицами:** `xlsx` (уже установлен и настроен в `lib/excelService.ts`).
* **Сборка и проверка:** Каждый этап разработки **обязан** успешно проходить `npm run build` с 0 ошибок TypeScript и Turbopack.
* **Кодировка файлов:** Все файлы проекта на Windows сохраняются строго в **UTF-8 без BOM**.

## 2. Критические правила безопасности (P0 Security & 152-ФЗ)

1. **Защита персональных данных (PII):** Запрещен вывод незамаскированных паспортных данных, ИНН, СНИЛС и контактов клиентов в логи, публичные API или открытый клиентский бандл.
2. **Изоляция прав (RLS):** Все таблицы клиентов (`clients`, `client_profiles`, `passports`, `tax_identity`, `children`, `spouses`, `client_documents`, `client_communications`, `manager_tasks`) закрыты RLS-политиками — доступ только для авторизованных менеджеров (`authenticated`).
3. **Хранилище файлов:** Все сканы хранятся только в приватном бакете. Прямой публичный URL запрещен. Доступ только по временным Signed URLs со сроком жизни до 300 секунд.
4. **Ключи:** `SUPABASE_SERVICE_ROLE_KEY` и `TELEGRAM_BOT_TOKEN` используются **только на сервере** (в Route Handlers или Server Actions) и никогда не попадают в код клиентских компонентов (`NEXT_PUBLIC_`).

## Модуль 1: Автогенерация официальных ведомственных бланков РФ (МВД, ФНС)

### Цель
Дать менеджеру возможность в 1 клик скачать или отправить на печать не просто сводное досье, а **реальный регламентированный бланк государственного образца** с подставленными из анкеты данными.

### Перечень реализуемых форм
1. **Форма 1П:** Заявление о выдаче (замене) паспорта гражданина РФ (утв. Приказом МВД России).
2. **Форма 2-2-Учет:** Заявление физического лица о постановке на учет в налоговом органе (получение ИНН).
3. **Уведомление о прибытии иностранного гражданина:** Бланк миграционного учета (отрывная и неотрывная части).
4. **Заявление на выдачу РВП / ВНЖ** (стандартное ведомственное заявление).

### Архитектура решения
* **Маршрутизация:** Создать Route Handler `/app/api/client/[id]/forms/[formType]/route.ts`, где `formType` принимает значения `passport-1p`, `tax-inn`, `migration-notice`, `rvp-vnzh`.
* **Метод генерации:**
  * *Рекомендуемый быстрый и масштабируемый подход:* HTML/CSS верстка по пиксельной сетке бланка (шрифт моноширинный, знакоместа для букв `.char-box { border: 1px solid #000; width: 18px; height: 24px; text-align: center; }`), оптимизированная для `@media print` и сохранения в PDF через диалог печати браузера (`window.print()`).
  * *Альтернативный подход:* Заполнение полей существующего PDF-шаблона с помощью библиотеки `pdf-lib` (бинарное наложение текста по координатам `X/Y`).
* **Интерфейс в CRM:**
  * В детальной карточке клиента (`selectedClient`) и в строке таблицы добавить выпадающее меню **«Официальные бланки ▾»**:
    * 📄 Бланк 1П (Паспорт РФ)
    * 📄 Бланк ИНН (Форма 2-2)
    * 📄 Миграционный учет (Регистрация)
    * 📄 Заявление РВП/ВНЖ

## Модуль 2: Интерактивная Канбан-доска (Drag & Drop Воронка)

### Цель
Повысить наглядность работы менеджеров: переключение между режимом таблицы реестра и визуальной Канбан-доской с перетаскиванием карточек клиентов по колонкам этапов.

### Статусы колонок воронки
1. 🔵 **Новые анкеты** (`new`)
2. 🟠 **В обработке** (`in_progress`) — менеджер связался, уточняет детали.
3. 🟣 **Ждем документы** (`need_docs`) — клиент собирает сканы/переводы.
4. 🔷 **Подано в ведомство** (`submitted`) — документы переданы в МВД/МФЦ/ФНС.
5. 🟢 **Готово / Оказано** (`completed`) — услуга завершена, паспорт/документ на руках.
6. ⚪ **Архив / Отказ** (`archived`).

### Архитектура и реализация
* **UI Переключатель:** Над таблицей реестра добавить переключатель вида:
  * `[ ☰ Список ]` | `[ ⊞ Канбан-доска ]` (сохранять выбранный вид в `localStorage`).
* **Библиотека DND:** Использовать проверенную и совместимую с React 19 / Next.js 16 библиотеку `@hello-pangea/dnd` (современный форк `react-beautiful-dnd`) либо легковесный нативный HTML5 Drag and Drop (`onDragStart`, `onDragOver`, `onDrop`).
* **Оптимистичный UI (Optimistic Updates):**
  * При перетаскивании карточка мгновенно переходит в новую колонку на экране.
  * Параллельно отправляется фоновый запрос к `updateClientStatus(clientId, newStatus)`.
  * При ошибке сети карточка возвращается на прежнее место с показом уведомления об ошибке.
* **Анатомия карточки Канбана:**
  * ФИО клиента, гражданство, возраст.
  * Быстрая кнопка прямого WhatsApp-чата.
  * Индикатор прикрепленных документов (например, `📎 3 скана`).
  * Дедлайн/дата регистрации.

## Модуль 3: Система Telegram-оповещений о новых анкетах

### Цель
Мгновенно доставлять уведомления руководству и дежурным менеджерам в Telegram при заполнении новой анкеты на сайте (время реакции менеджера сокращается до 1–3 минут).

### Конфигурация
* Переменные окружения в `.env.local` (и в Vercel Environment Variables):
  ```env
  TELEGRAM_BOT_TOKEN="123456789:ABCdefGHIjklMNOpqrSTUvwxYZ"
  TELEGRAM_CHAT_ID="-1001234567890" # ID группы менеджеров или личный ID руководителя
  ```
* Сервисный модуль: `lib/telegramService.ts`.

### Логика отправки
* Вызывается в Server Action `submitQuestionnaireAction` (или обработчике сохранения анкеты) сразу после фиксации клиента в базе данных.
* **Шаблон сообщения (HTML):**
  ```text
  🔥 <b>Новая анкета клиента на сайте!</b>

  👤 <b>ФИО:</b> Рахимов Алишер Баходирович
  🌍 <b>Гражданство:</b> Республика Таджикистан
  📞 <b>Телефон:</b> +7 (926) 123-45-67
  💬 <b>WhatsApp:</b> <a href="https://wa.me/79261234567">Написать клиенту</a>
  📑 <b>Паспорт/Услуга:</b> ВНЖ / Паспорт РФ
  ⏰ <b>Дата:</b> 06.09.2026, 14:30

  🔗 <a href="https://gosuslugi-olive.vercel.app/admin">Открыть карточку в CRM</a>
  ```
* **Безотказность (Graceful Fallback):** Ошибка отправки в Telegram не должна блокировать сохранение анкеты для клиента. Оборачивать в `try { ... } catch (err) { console.error(...) }`.

## Модуль 4: Модуль контроля сроков документов и повторных продаж (Deadlines)

### Цель
Превратить CRM в инструмент генерации повторной выручки (LTV). Миграционные документы имеют ограниченный срок действия. Система должна заранее предупреждать менеджера о необходимости продления.

### Отслеживаемые типы сроков
1. **Регистрация / Миграционный учет:** 90 суток с даты въезда / продление на 1 год.
2. **Трудовой патент:** ежемесячная оплата налога / продление на 12 месяцев.
3. **Паспорт РФ по возрасту:** наступление 20 лет и 45 лет (автоматический расчет по полю `birth_date`).
4. **Заграничный паспорт:** окончание срока действия (за 6 месяцев до даты многие страны и консульства запрещают выезд).
5. **ВНЖ / РВП:** контрольные даты ежегодного подтверждения проживания.

### Архитектура модуля
* Создать сервисный хелпер `lib/deadlineService.ts`:
  * Функция `calculateClientDeadlines(client: ClientData): DeadlineAlert[]`.
  * Цветовая индикация:
    * 🔴 **Критично:** срок истекает через ≤ 14 дней или уже просрочен.
    * 🟡 **Внимание:** срок истекает через 15–30 дней.
    * 🟢 **В норме:** > 30 дней.
* **Интерфейс в панели:**
  * Во вкладке «Аналитика / Dashboard» блок **«Контроль сроков и повторные продажи»**.
  * Кнопка рядом с каждым клиентом в блоке: *«Позвонить для продления»* (сразу формирует задачу в таск-трекер менеджера).

## Модуль 5: Календарь записей на прием и сопровождение

### Цель
Фиксировать даты визитов клиентов в офис компании, а также даты совместной поездки с юристом/сопровождающим в ведомства (МФЦ, МВД, Сахарово).

### Модель данных (Supabase SQL)
```sql
CREATE TABLE IF NOT EXISTS client_appointments (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  client_id TEXT REFERENCES clients(id) ON DELETE CASCADE,
  appointment_date TIMESTAMP WITH TIME ZONE NOT NULL,
  type VARCHAR(50) NOT NULL, -- 'office_visit', 'mvd_submission', 'mfc_submission', 'consultation'
  location TEXT,             -- Адрес офиса или ведомства
  manager_name VARCHAR(100) DEFAULT 'Дежурный менеджер',
  status VARCHAR(30) DEFAULT 'scheduled', -- 'scheduled', 'completed', 'cancelled', 'no_show'
  notes TEXT,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT timezone('utc'::text, now())
);
```

### Функционал
* Простой интерактивный календарь (месяц / неделя) на базе легковесного компонента.
* Кнопка в карточке клиента: **«+ Назначить визит / подачу»**.
* **Шаблон напоминания в WhatsApp:** по клику генерирует клиенту сообщение:
  > *«Здравствуйте, [Имя]! Напоминаем, что запись на подачу документов назначена на 15 сентября в 10:00 по адресу: г. Москва, ул. ... Не забудьте взять с собой оригиналы паспорта и перевода»*.

## Модуль 6: Ролевая модель доступа и разграничение прав (RBAC)

### Цель
Защитить бизнес заказчика от утечки базы клиентов сотрудниками и исключить случайное удаление данных.

### Матрица прав доступа

| Действие / Раздел | Роль `admin` (Владелец) | Роль `manager` (Менеджер) | Роль `operator` (Ввод) |
| :--- | :---: | :---: | :---: |
| Просмотр всех клиентов | ✅ Да | ✅ Только назначенные | ❌ Нет |
| Ввод новой анкеты | ✅ Да | ✅ Да | ✅ Да |
| Редактирование анкеты | ✅ Да | ✅ Да | ❌ Только черновики |
| Скачивание Excel реестра | ✅ Да | ❌ Запрещено | ❌ Запрещено |
| Удаление клиента из базы | ✅ Да | ❌ Запрещено | ❌ Запрещено |
| Просмотр сканов документов | ✅ Да | ✅ Да | ✅ Загрузка без удаления |
| Настройка цен и услуг | ✅ Да | ❌ Нет | ❌ Нет |

### Архитектура реализации
1. В таблице пользователей Supabase Auth сохраняется `user_metadata.role` (`'admin' | 'manager' | 'operator'`).
2. В интерфейсе кнопки «Экспорт в Excel» и «Удалить клиента» рендерятся по условию: `userRole === 'admin'`.
3. В Route Handlers экспорта и удаления проверяется сессия сервера и соответствие роли.
